=== TASK 17.11 — DECRYPT API KEYS AT POINT OF USE ===
Date: 2026-11-27

ROOT CAUSE (R6, confirmed in 17.0)
`cmd_mission_send_prompt` took `c.api_key_encrypted` straight from the DB and
passed the `enc_v1:` blob as `api_key` to `InferDispatcher::dispatch_stream`.
`decrypt_api_key` existed but was only called in a test. Every cloud request
therefore sent an armored blob as the bearer token.

CHANGES
- crates/starship-db/src/models.rs: added `SecretString` (redacted `Debug`)
  and `Database::get_provider_credentials(provider_id) ->
  Result<Option<SecretString>, CoreError>`; decrypts via `decrypt_api_key`.
  `Result` is used instead of the plan's `Option` because decryption can fail.
- crates/starship-db/src/lib.rs: re-exported `SecretString`.
- app/src-tauri/src/ipc/commands.rs: added `resolve_cloud_credentials(db,
  provider_type)` — the only path from the encrypted column to an HTTP client;
  `cmd_mission_send_prompt` now uses it. Local models return `(None, None)`.
- No API.md/DATABASE.md change: no Tauri command, event, event payload or
  SQLite schema was added or altered (internal DB helper only).
