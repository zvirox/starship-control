# AGENTS.md — Contributor & AI Agent Rules

This file is the primary binding contract for any human contributor or AI coding assistant working in this repository. It governs every task, every commit, and every pull request without exception.

---

## 1. Project Summary (5 lines)

1. **Starship Control** is a local-first, native Linux AI agent orchestrator and unified command center for desktop applications (Easy Edits Pro, ScreenStudio Pro, Audio Labs Pro, Net Watch Pro, Agentic Tuneup Pro).
2. **Dual Engine Model Support:** Executes local GGUF models directly on hardware (Vulkan/ROCm/CPU) via `llama-cpp-2` with an in-app Hugging Face downloader, or connects to external cloud APIs (OpenAI, Anthropic, Gemini, OpenRouter).
3. **Dual-Surface Interface:** Single Rust core driving two Tauri 2 surfaces: the **Cockpit** (`1280×800` primary strategic window, min `1024×640`, `decorations: false`, `transparent: false`, 40px TitleBar + 240px collapsible Sidebar) and the **Floating HUD** (`420×64` opaque solid bar, `6px` radius, `transparent: false`, drag handle + logo + close, synced with Cockpit theme).
4. **App Ecosystem & Bridge:** Auto-discovers sub-applications via `$XDG_DATA_HOME/starship/plugins/*.json` manifests generated by the shared `starship-plugin` SDK; executes commands over Unix domain sockets with Linux `SO_PEERCRED` (live GUI) or headless stdio MCP child processes.
5. **Tiered Safety Enforced in Native Code:** Read-only inspections execute autonomously; mutating (Tier 2) and destructive (Tier 3) operations strictly pause execution awaiting signed human approval on the HUD or Cockpit.

## 3. Mandatory Requirements (DO)

1. **Adhere to the Cargo Workspace Structure:**
   - `crates/starship-core`: Planning (`tasksheet/1` + GBNF + repair loop), safety policy, execution state machine, resource admission, context assembling.
   - `crates/starship-infer`: Local GGUF runner facade & VRAM guard (native `llama-cpp-2` bindings pending), Hugging Face chunked downloader, cloud SSE clients (OpenAI, Anthropic, Gemini, OpenRouter).
   - `crates/starship-mcp`: MCP client pool, Unix domain socket transport with `SO_PEERCRED` + binary/manifest trust checks, stdio child spawner.
   - `crates/starship-plugin`: Shared Rust SDK crate imported by sub-apps (EEP, SSP, ALP, NWP, ATP).
   - `crates/starship-db`: SQLite connection pool, migrations (`0001`–`0006`), queries, tamper-evident hash-chained audit logging.
   - `crates/starship-health`: Live CPU, RAM, swap, PSI, disk, thermal, and GPU telemetry samplers, ring buffer, and overload detector.
   - `crates/xtask`: Workspace build/evaluation CLI utilities (`planner-eval`, schema/router benchmarking).
   - `app/`: Tauri 2 desktop shell (`src-tauri/`) and React 19 frontend (`src/`), guarded by `npm run check:linear`.
2. **Strict Enforcement of Tiered Safety:**
   - Never allow an LLM tool call to execute mutating or destructive operations without passing through the Rust `SafetyArbiter`.
   - Mutating steps require a verified, signed user token issued from the approval UI.
3. **Type Parity Across IPC:**
   - Every Tauri command and event payload in `app/src-tauri/src/ipc/` must have an exact TypeScript mirror in `app/src/types/ipc.ts`.
4. **Standard Error Handling:**
   - All Rust failures must map to `CoreError` with a canonical error code (`API.md §1`).
   - Render plain-English copy (`userMessage`) in the UI; write detailed debug stacks to rotating tracing logs on disk only.
5. **Prompt Injection Defense:**
   - Strings originating from external applications, file names, window titles, or CET sidecars must be wrapped inside `<untrusted_context>` blocks in prompt templates.
6. **Design Law & Token Fidelity:**
   - Use only tokens defined in `app/src/styles/linear-theme.css` and mirrored in `DESIGN.md`. Never introduce arbitrary hex codes or custom font families outside that file.
   - Surfaces must implement the Linear solid opaque specifications (`--bg-app`, `--bg-sidebar`, `--bg-surface`, `--bg-surface-2`) with 1px hairlines, zero translucency except `--scrim` and chart fades, zero blur, and the single allowed `--shadow-card`.
7. **Verification Before Completion:**
   - Before claiming any task is done, run and verify:
     - `cargo fmt --check`
     - `cargo clippy --workspace --all-targets -- -D warnings`
     - `cargo test --workspace`
     - `npm run lint` & `npm run typecheck` (in `app/`)
   - Present verifiable command output as proof.

## 4. Hard Constraints (DO NOT)

1. **Do NOT alter the Tech Stack:** Rust 2024 + Tauri 2 + React 19 + TypeScript + Tailwind CSS v4 + SQLite WAL is final.
2. **Do NOT introduce unapproved dependencies:** Any new external crate or npm package requires explicit justification against existing workspace utilities.
3. **Do NOT hardcode secrets or API keys:** All keys are stored in the SQLite database (with Secret Service API support) and strictly scrubbed from logs and prompts.
4. **Do NOT bypass `SO_PEERCRED`:** Every Unix domain socket connection to a sub-application must verify peer credentials to ensure the connecting process belongs to the host user.
5. **Do NOT duplicate sub-application engines:** Starship Control orchestrates and commands; it does not implement raw video rendering, audio mixing, or network packet capture.
6. **Do NOT execute destructive file operations silently:** Wiping caches (ATP), modifying timelines (EEP), or deleting audio takes (ALP) requires explicit user confirmation.
7. **Do NOT skip accessibility:** All controls must support keyboard navigation with the universal focus ring (`0 0 0 2px <bg>, 0 0 0 4px var(--primary-text)`), ARIA labels, and reduced-motion compliance.

## 5. Standard Task Workflow

For every implementation task from `PLAN.md`:

```
1. RECONNAISSANCE ──► Read governing spec (PRD, ARCH, DESIGN, etc.) & callers.
2. IMPLEMENTATION ──► Write minimal, surgical code conforming strictly to the crate tree.
3. VERIFICATION   ──► Run compiler, clippy -D warnings, typecheck, and unit/integration tests.
4. CONTRACT SYNC  ──► Update API.md, DATABASE.md, or PLAN.md if additions were made.
5. COMMIT         ──► Create concise, conventional commit with proof of verification.
```
